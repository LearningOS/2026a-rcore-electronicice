# Lab 2：地址空间与内存管理

## 实现总结

本实验在每个任务独立地址空间的基础上，实现了 `mmap`、`munmap`、虚拟内存环境下的 `get_time` 与 `trace`。实现遵循统一的工程分层：系统调用层检查和解释用户参数，任务管理层定位当前任务，内存管理层维护 `MemorySet`、页表项和物理页帧。

最终形成两个闭环：

```text
建立映射：用户请求 → 参数检查 → 当前任务 MemorySet → 检查冲突 → 建立页表映射
销毁映射：用户请求 → 参数检查 → 验证完整区间 → 删除页表项和区域记录 → 释放物理页
```

对于用户指针，内核不再直接解引用，而是使用当前任务的页表验证地址及 `U/R/W` 权限，再访问对应物理页。

## 实验一：建立映射 `mmap`

### 问题

用户给出起始虚拟地址、长度和权限后，内核需要为当前任务建立一段新的虚拟内存映射，同时拒绝非法参数和重复映射。

### 实现流程

```text
sys_mmap(start, len, prot)
  → 检查页对齐、长度、权限位和地址溢出
  → 将 prot 转换为 MapPermission
  → task::mmap_current 定位当前任务
  → MemorySet::insert_framed_area_checked 检查目标虚拟页
  → insert_framed_area 分配物理页并建立映射
```

系统调用层只处理 API 规则；是否已经存在映射属于当前 `MemorySet` 的内部状态，因此冲突检查放在内存管理层。若发现任意目标页已经有效，返回 `-1`，避免底层 `PageTable::map` 的断言使整个内核 panic。

### 权限转换

```text
prot bit 0 → R
prot bit 1 → W
prot bit 2 → X
所有用户映射同时具有 U
```

## 实验二：销毁映射 `munmap`

### 问题

解除映射不能只清除一个页表项，还必须同步维护映射区域记录并释放相应物理页，否则会产生状态不一致或内存泄漏。

### 实现流程

```text
sys_munmap(start, len)
  → 检查页对齐和地址溢出
  → task::munmap_current 定位当前任务
  → MemorySet::remove_framed_area_checked 验证整个区间
  → 清除页表项
  → 移走并释放 FrameTracker
  → 保留或拆分未被删除的 MapArea
```

实现先验证整个目标区间，再开始修改。这样若区间中存在未映射页面，函数直接返回 `-1`，不会只删除一半后留下不完整状态。

若只删除一个 `MapArea` 的中间部分，原区域需要拆成左右两个子区域。`take_subarea` 将仍然有效的 `FrameTracker` 转移到新的区域；被删除部分的追踪对象在离开作用域后释放物理页。

## 实验三：虚拟地址环境下安全访问用户内存

### 问题

用户传给系统调用的指针只是用户地址空间中的虚拟地址。内核若直接解引用，可能访问未映射地址、只读页面或内核页面。因此新增了一层用户内存访问契约。

### 内部接口

```text
read_user_byte(token, addr)
  → 合法且具有 U|R：返回一个字节
  → 否则：返回 None

write_user_byte(token, addr, value)
  → 合法且具有 U|W：写入并返回 true
  → 否则：返回 false

copy_to_user(token, dst, bytes)
  → 先验证完整目标范围，再跨页复制
  → 任意页面非法时不写入并返回 false
```

`user_page` 负责完成共同检查：地址格式正确、页表项有效、页面属于用户空间，并具有本次操作所需的读写权限。成功后返回物理页号和页内偏移。

`copy_to_user` 使用“先完整验证、后写入”的两阶段设计。如果 `TimeVal` 跨越两个页面，而第二页不可写，函数不会先修改第一页再失败。

## 实验四：`get_time` 与 `trace`

### `get_time`

```text
sys_get_time(ts)
  → get_time_us 得到微秒数
  → 分解为 sec 和 usec
  → copy_to_user 写入用户 TimeVal
  → 成功返回 0，用户地址非法返回 -1
```

这里内核先生成自己的 `TimeVal`，再经过当前任务页表复制到用户地址，而不是直接使用用户指针。

### `trace`

```text
request = 0：id 解释为用户地址，安全读取一个字节
request = 1：id 解释为用户地址，将 data 的低八位安全写入
request = 2：id 解释为 syscall 编号，查询当前任务的计数表
```

系统调用计数在统一入口、分发具体 syscall 之前增加。因此查询 `SYSCALL_TRACE` 时，本次查询本身已经计入，符合实验要求。

## 核心验证原理

本实验的验证不依赖罗列具体用例，而是检查四类性质：

1. **成功路径**：建立映射后必须能够按设定权限实际访问，不能只检查系统调用返回值。
2. **拒绝路径**：地址、范围或权限非法时，应在修改状态前返回错误，避免内核 panic 或产生部分修改。
3. **生命周期闭环**：解除映射后，该地址应失效；再次建立映射时又应恢复可用，证明页表、区域记录和物理页状态保持一致。
4. **隔离与回归**：用户错误只能影响当前任务；新增功能不能破坏已有的任务切换、系统调用和内存功能。

这些原则对应“正常输入、错误输入、状态反转、旧功能不受影响”四个观察角度。它们用于证明抽象契约成立，而不是要求我现在掌握测试框架的全部实现。
